## A. Current state — technical inventory

### Platform & code
- **Framework:** Next.js **16.3.4** (App Router) + React 19 + TypeScript 5.
- **Styling:** Tailwind CSS **v4** — CSS-first configuration in
  `src/app/globals.css` (no `tailwind.config.js`).
- **Language/tooling:** TypeScript strict mode; ESLint (`eslint-config-next`).
  Scripts: `dev`, `build`, `start`, `lint`.
- **Path alias:** `@/*` → `src/*`.
- **App type:** a Node.js server-rendered app built with `next build`/`next start`
  (no static-only export configured). Output can be hosted on Node-capable
  platforms but can also run on static/CDN platforms via adapters.
- **Repository:** Git repo, single local commit. **No remote (GitHub/GitLab)
  repository, CI/CD, or deployment pipeline exists yet.**

### Domain & identity
- All canonical URLs, `sitemap.xml`, `robots.txt`, Open Graph and JSON-LD use
  **https://www.meltz.co.zm**.
- **The domain is not yet registered or pointed anywhere.**
- PWA manifest named "MELTZ"; app icons (`icon.png`, `apple-icon.png`) exist.

### Email
- Public contact email: **info@meltz.co.zm** (needs a mailbox to be set up).
- Staff email on the Contact page: **gphiri@meltz.com.zm** —
  **two different domains (meltz.co.zm vs meltz.com.zm) — confirm which is the
  official one.**

### Contact form
- The form (`ContactForm.tsx`) validates input and has a spam honeypot, but
  **does not send data anywhere** — it simulates success after ~600 ms.
- **A real backend is required before launch** (API route, email provider, or
  form service).

### Security (already implemented)
- Security headers on all routes:
  - `X-Frame-Options: SAMEORIGIN` (blocks clickjacking)
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- Image optimisation (AVIF/WebP) enabled; SVG served sandboxed,
  download-only (`dangerouslyAllowSVG` with CSP).
- No secrets, API keys, or credentials in the repository.
- No custom TLS configuration needed at app level — provided by hosting/CDN.

### Search & discoverability
- Generates **sitemap.xml** (all pages + news), **robots.txt**, and structured
  data (JSON-LD: Organisation, Breadcrumbs, Products, Articles).
- Per-page SEO metadata (title/description/canonical/Open Graph/Twitter).

## B. Deployment options (hosting)

The site is a small corporate site; options below cover the realistic range.

| Option | Monthly cost | Pros | Cons |
|---|---|---|---|
| **A. Vercel (Hobby/Pro)** | $0 / $20 per seat | Purpose-built for Next.js; free tier fine for launch; preview deploys; SSL/CDN included | Pro bills per seat (5 seats = $100/mo) |
| **B. Netlify (Free/Personal/Pro)** | $0 / $9 / $20 flat (unlimited members) | Flat team pricing; free contact forms; 30-day analytics on Pro | Credit-based fair-use model |
| **C. Cloudflare Pages** | $0 (Pages) + $0–5 (Workers) | Unlimited bandwidth, global CDN, free tier is generous | Next.js setup slightly more involved |
| **D. Company server / VPS** | $10–50 + admin time | Full control, in-country or cloud | Patching, security, backups, uptime are **your** job; higher effort/risk |

**Recommendation for MELTZ:** start on the **free tier of a managed platform
(Vercel or Netlify)** to go live at $0 hosting, then step up to a paid tier
only if traffic/needs grow. Avoid a self-managed VPS unless the company already
runs servers in-house.

## C. Decisions needed from IT

1. **Domain** — confirm `www.meltz.co.zm`; who registers it (Zambia-resident
   registrar required for `.co.zm`, ~US$127–160 registration, ~US$142/yr
   renewal), who owns the registrar account, and who renews it each year.
2. **Hosting platform & account** — choose option A–D above; confirm the
   business/company account holder and that it is a company (not personal)
   account so access survives staff changes.
3. **Email** — confirm the official domain for public email and set up
   mailboxes (see costs below). Ensure all mailboxes shown on the site are
   monitored.
4. **Contact form backend** — approve how enquiries are delivered (e.g. email to
   a shared inbox via a form/email provider) and confirm the recipient mailbox
   and monitoring rota.
5. **Source control & CI/CD** — create a private remote Git repo (GitHub/GitLab)
   and a deploy pipeline (auto-deploy on push to `main`). Confirm who has
   write access.
6. **Security sign-off** — approve the current headers/settings or request
   changes; schedule an annual security review.
7. **Analytics & monitoring** — enable web analytics (free: Google Analytics /
   Search Console / platform analytics) and an uptime alert (e.g. free-tier
   uptime monitor). Set a review cadence.
8. **Backups & recovery** — define what is backed up (code repo, content,
   configuration) and how a restore is tested. Document a simple recovery runbook.
9. **Staging** — confirm a preview/staging branch (`develop`/`staging`) so
   changes are tested before production.
10. **Content update process** — decide who edits content, how changes are
    requested, and whether a **CMS** is needed (see costs below) vs. editing
    code files through IT.
11. **Legal / compliance** — confirm whether a **privacy policy** and
    **cookie/terms** page are required (they are strongly recommended) and who
    drafts them.
12. **Access & ownership register** — document every account (domain registrar,
    hosting, email admin, analytics, Git) with owner, password manager, and
    successor. This matters for business continuity.
13. **SSL/TLS** — confirm automatic HTTPS is relied on from the hosting platform
    (no manual certificates needed).
14. **Budget** — confirm the cost envelope (see Section D) and who pays invoices.
